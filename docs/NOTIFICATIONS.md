# Уведомления: Redis vs PostgreSQL

## Рекомендация: Redis для очереди, БД для истории (по желанию)

### Redis — очередь уведомлений
- **Очередь задач**: новые уведомления складываются в список `notifications:queue`
- **Потребитель**: бот или отдельный воркер забирает из очереди (`BLPOP`) и отправляет в Telegram
- **Плюсы**: быстрая запись, не нагружает БД, подходит для частых событий (запись в поездку, напоминания)
- **Минусы**: при падении Redis часть очереди может потеряться (если не использовать AOF)

### PostgreSQL — лог уведомлений (опционально)
- **Таблица** `notification_log`: `id`, `user_id`, `trip_id`, `type`, `text`, `sent_at`, `read_at`
- **Использование**: аудит, статистика «кто что получал», повторная отправка
- **Когда имеет смысл**: если нужна история или отчёты по уведомлениям

### Как использовать
1. При событии (например, пользователь присоединился к поездке) вызывать `push_notification(tg_id=creator_id, text="...", notification_type="trip_join", trip_id=...)`
2. В боте или воркере в фоне: цикл `while True: n = await pop_notification(); if n: await bot.send_message(n["tg_id"], n["text"])`
